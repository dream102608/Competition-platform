# 竞赛一体化管理平台 · 小程序 V1.3（版本说明）

> 在 V1.2 多级评审与手写签名之上，深化**审批链可信度**与**数据洞察**：哈希加封防伪链、统计报表中心、微信服务通知订阅（演示级）。
> 视觉延续「墨纸编辑部」设计语言；数据层继续云优先 + Storage 回落，纯前端零配置演示。

---

## 一、本版本功能（V1.3 做了什么）

| 模块 | 功能 |
| --- | --- |
| **签名防伪 · 哈希加封链** | 审批节点「加封」：每次提交 / 重提 / 签批后，按节点内容（名称·审批人·状态·时间·批语·签名·前驱哈希）重算 djb2 指纹，逐节点写入 `prevHash + hash`，形成链式绑定——**任何单点改动都会断链** |
| **防伪校验弹窗** | 学生端「我发起的」与审批人「我处理过的」均可点「⌑ 防伪校验」：重算整链逐节点核验（✓/✗ + 指纹），结论印章「卷宗完整 · 未被篡改」或「链上异常 · 发现 N 处改动」 |
| **链上指纹可视化** | 轨迹每个节点显示「链上指纹 0x********」，手签节点显示「签署 09.02 14:05 · 指纹 …」——加封状态人人可见 |
| **旧数据自动补封** | V1.2 及更早写入的卷宗没有哈希字段：首次校验时自动补封（幂等），弹窗标注「已自动补封后核验」，无需清空存储 |
| **统计报表中心（新页）** | 审批角色专属报表页：总览票（总量 / 审批中 / 已驳回 / 已通过 + 通过率 / 覆盖队员 / 平均每队人数）；纸墨风纯 CSS 条形图（按赛项 / 指导教师负载 / 赛道构成）+ 状态堆叠条与图例 |
| **筛选导出（增强）** | 报表页「导出」区：全部 / 审批中 / 已驳回 / 已通过 / 已撤回 五档筛选 chips（带计数）→ `exportCSV(statusFilter)` 按筛选生成 CSV，弹窗一键复制 |
| **服务通知订阅（演示）** | 设置页新增「微信服务通知」开关（V1.3 角标）：开启即调 `wx.requestSubscribeMessage` 请求授权；演示环境未配置模板 ID 时**诚实降级**提示并继续走站内信 |
| **工作台快捷入口** | 审批人首页卡片新增「⌑ 统计报表 / ◔ 消息中心(未读角标)」双快捷入口；审批中心页头新增「报表」按钮 |

### 角色路由总览（V1.3）
```
登录页选身份 → app.login(role)
├── student → 首页学生视图 → 审批页「我发起的」
│    ├── 队伍管理 / 附件预览 / 催办 / 改完重交
│    └── ⌑ 防伪校验：整链哈希逐节点核验（旧卷宗自动补封）
└── teacher / dept / college / school → 首页工作台（⌑ 报表 / ◔ 消息）
     ├── 审批中心「待我审批」→ ✎ 签名通过（写入 signTime + 重加封）/ 模板驳回
     ├── 「我处理过的」→ ⌑ 防伪校验
     └── 统计报表中心：聚合图表 + 五档筛选导出 CSV
```

## 二、代码说明

### 数据层 `utils/data.js`（V1.3 新增/调整）
| API / 函数 | 说明 |
| --- | --- |
| `hashStr(str)` | djb2 变体 32 位可复现哈希，返回 `0x` + 8 位十六进制指纹（模块内私有） |
| `fingerprint(node)` | 节点指纹 = 名称·审批人·状态·时间·批语·`prevHash`·签名摘要（长度+哈希）级联后哈希；签名以“长度+哈希”参与，避免全文入串仍能绑定 |
| `sealReg(reg)` | 加封整链：逐节点写 `prevHash`（首节点为 `'root'`）+ `hash` |
| `act(regId, action, note, signature)` | **签批即加封**：pass 带签名时写 `node.signTime`；动作后 `sealReg(reg)` + `reg.sealedAt`，再落盘 |
| `submitRegistration / resubmit` | 提交 / 重提后同样重新加封 |
| `verifyChain(regId)` | 防伪校验：缺封的旧卷宗先自动补封（幂等，写回）；随后逐节点核验 `prevHash` 衔接与自身哈希，返回 `{ ok, total, bad[], items[{name,ok,fp,time}], autoSealed }` |
| `reportStats()` | 报表聚合：总量/四态计数/通过率/队员数/平均队型 + 按赛项、赛道、指导教师降序数组 + `statusSeq` 四态序列 |
| `exportCSV(statusFilter)` | 原 9 列导出增加可选筛选参数（`''` 或 `'all'` = 全量，V1.2 调用方式不变，向后兼容） |
| `getPrefs()` | 默认值增加 `subscribe: false`（微信服务通知订阅开关） |

> **防伪语义边界（如实说明）**：客户端哈希能拦截「改数据不改哈希」的篡改与传播路径演示，属演示级完整性校验；正式环境须由服务端用私钥对节点做签名（`HMAC`/国密）才能真正防伪。此边界已写入 V1.4 计划。

### 审批页 `pages/approval/`（V1.3 增量）
- 节点装饰 `decoNode`：克隆节点并附 `fp8`（哈希前 9 位），轨迹直接渲染指纹，不污染存储对象。
- `verify(e)` → `data.verifyChain(id)` → 弹层 `vrf-*` 逐行核验；旧卷宗自动补封后 `refresh()` 刷新指纹。
- 页头「报表」→ `goReports()`（`navigateTo`）；学生/审批人「我处理过的」均提供 ⌑ 防伪校验按钮。

### 报表中心 `pages/reports/`（V1.3 新页）
- 纯前端聚合 `data.reportStats()`，无图表库——全部用纸墨风 CSS 手绘：
  `.rp-bar` 描边墨条 + `.rp-bar-fill` 朱砂/靛蓝/墨灰填充（宽度按最大值归一化），`.rp-stack` 四态堆叠条（`statusSeq` pct 宽度 + 状态色），图例 `.rp-leg`。
- 角色守卫：非审批角色只显示「仅对评审台开放」+ 回首页；`filters` chips 带计数、选中荧光黄；导出调用 `exportCSV(filter)` 复用数据层。
- 已在 `app.json` 注册为第 10 页（非 tab），自定义头部自带 `‹` 返回。

### 设置页 / 首页（V1.3 增量）
- `settings.js`：`onSubscribe` 开启时 `wx.requestSubscribeMessage(['JINGSAI-DEMO-APPROVAL','JINGSAI-DEMO-URGE'])`，成功提示已订阅 / 失败提示“未配置模板 ID 先走站内信”；版本号 → V1.3.0。
- `home.js`：工作台卡新增 `goReports`；卡片底部 `.tea-links` 双快捷入口（报表 / 消息带未读角标）。

### 兼容性
V1.0 / V1.1 / V1.2 已写入的 Storage **无需清空**：旧卷宗无哈希字段 → 首次防伪校验时自动补封；`exportCSV` 无参调用行为与 V1.2 完全一致；新增键仅 `prefs.subscribe`（默认关）。重置路径：我的 → 重置演示数据。

## 三、下一版本迭代功能（V1.4）

- **服务端签名防伪**：节点哈希改由服务端私钥签名（HMAC/国密），客户端只验签不产签——关闭客户端哈希的演示级边界
- **云开发正式接入**：报名单 / 消息 / 队伍集合云端化、多端实时同步，替换 Storage 主路径（报表数据源同步云端）
- **订阅消息正式化**：小程序后台申请模板 ID → `requestSubscribeMessage` 走真推送；审批通过 / 驳回 / 催办按事件下发服务通知
- **知识广场（V2.0 前置，自 V1.3 顺延）**：经验帖 / 获奖名单 / 模板下载，先做静态列表版（首页宫格占位位已预留）
- **报表增强**：XLSX 导出（sheetjs）、日期/赛项筛选、教师个人绩效页
- **通知分组**：消息中心按 审批 / 催办 / 公告 分页签
