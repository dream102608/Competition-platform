# 竞赛一体化管理平台 · 小程序 V1.1（版本说明）

> 在 V1.0 学生赛道闭环基础上，补齐**教师端审批工作台**与**消息协同**能力。
> 视觉延续「墨纸编辑部」设计语言，页面结构兼容 V1.0 数据（无需清空本地存储）。

---

## 一、本版本功能（V1.1 做了什么）

| 模块 | 功能 |
| --- | --- |
| **教师端审批工作台** | 登录页教师票根启用（V1.1）。审批页按角色分流：教师看到「待我审批 / 我处理过的」双 Tab，待办卡片带「待审批章」+ 节点轨道 + 手写签名区 + 模板驳回（4 条批语）/ 通过盖章；审批链中**我经手的节点**荧光黄左标高亮。tabBar「审批」角标显示待办数 |
| **消息与催办中心** | 新页 `messages`：「来函」版式消息流，三类消息（公告靛蓝 / 审批朱砂 / 催办荧光黄）票据印章区分；未读红点 + 顶部「全部已读」；点击带关联报名单的消息 → 自动跳转审批页展开对应卷宗；`urge/act/resubmit` 都会产生新消息 |
| **首页铃铛角标** | 报头右侧铃铛 + 未读角标 → 消息中心；教师登录后首页切换为教师工作台卡片（待办/已处理统计 + 进入审批中心） |
| **账号设置** | 新页 `settings`：昵称 / 一句话签名编辑（保存到 user 档案，我的页封面显示签名）；通知偏好三开关（审批动态 / 催办提醒 / 系统公告，关闭后新消息不入箱）；清除缓存（消息·日志·收藏） |
| **真实文件上传** | 云开发可用时 `wx.chooseMessageFile` → `wx.cloud.uploadFile`（文件存云存储，显示 fileID）；未开通时回落 800ms 模拟上传，流程不断 |
| **我的页** | 新增「消息与催办」入口（未读角标）、「账号设置」入口；档案封面显示一句话签名 |

### 角色路由总览
```
登录页选身份 → app.login(role)
├── student → 首页学生视图（报名进度卷宗）→ 审批页只显示「我发起的」
└── teacher → 首页教师工作台卡片（陈默 / TEA-2019-0042）→ 审批页「待我审批 / 我处理过的」
```

## 二、代码说明

### 数据层 `utils/data.js`（新增 API）
| API | 说明 |
| --- | --- |
| `mockUser(role)` | 支持 teacher（陈默）/ admin（教务管理员）档案 |
| `getTeacherQueue(teacherName)` | 按审批人拆「待我审批 / 我处理过的」，以节点 `approver === 教师名` 匹配 |
| `getMessages / pushMsg / unreadCount / markAllRead` | 消息引擎，类型 `notice / approval / urge`；`pushMsg` 受通知偏好过滤 |
| `getPrefs / savePrefs` | 通知偏好（默认全开）持久化到 `js_prefs` |
| `saveUser / clearCache` | 用户档案持久化 / 清消息·日志·收藏 |
| `act / urge / resubmit` | 均追加 `pushMsg`：审批通过/驳回/重交/催办实时生成来函 |

### 审批页 `pages/approval/`
`refresh()` 按 `user.role` 分流；教师侧 `wx.setTabBarBadge` 显示待办数；`data.act(id, 'pass'|'reject', note)` 推进审批链并落消息；wxml 里 `node.approver === teacherName` 的节点加 `.mine`（荧光黄左标）样式。

### 新页面
- `pages/messages/`：`open()` 点消息 → 标已读 + `app.globalData.currentReg` 传参 + `switchTab` 到审批页自动展开。
- `pages/settings/`：`saveProfile()` 合并写 `globalData.user` + `js_user`；switch 组件绑定 `toggle` 落 `js_prefs`。

### 种子数据调整（教师演示可跑）
- `reg-0042` 白鹭队 → 指导教师改陈默、停留在「指导教师审批」节点（陈默的待办）
- `reg-0913` 无线充球队 → 指导教师改陈默、被陈默驳回（陈默的处理记录）
- `reg-0817` 夜航西飞 → 指导教师陈默已通过（陈默的处理记录）

### 兼容性
V1.0 已写入的 Storage 可直接升级（V1.1 只新增键 `js_msgs / js_prefs`，不破坏旧数据）；演示数据重置路径：我的 → 重置演示数据。
